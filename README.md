# vpsmajani — Windows RDP همیشه روشن (زنجیره‌ای)

یک ماشین ویندوز ابری روی GitHub Actions که Remote Desktop (RDP) و Tailscale دارد و **خودش را دوباره راه‌اندازی می‌کند**؛ یعنی وقتی یک سشن تمام می‌شود، سشن بعدی به‌طور خودکار استارت می‌خورد.

---

## مهم: محدودیت ۶ ساعته‌ی گیت‌هاب

روی رانرهای GitHub-hosted هر جاب **حداکثر ۶ ساعت** می‌تواند اجرا شود. این یک سقف سخت زیرساختی است و با `timeout-minutes` قابل بالا بردن نیست (هر چه بزرگ‌تر بنویسی، باز هم سر ۳۶۰ دقیقه کشته می‌شود). پس تنها راه «تموم نشدن» این است که:

> هر سشن کوتاه (≈۴۵ دقیقه) نگه داشته شود و **قبل از مرگش، سشن بعدی از طریق GitHub API دیسپچ شود**. این کار در جاب `next` انجام می‌شود.

نتیجه: ماشین همیشه برمی‌گردد، ولی هر بار یک VM تازه است (آی‌پی تازه، سیستم تازه). فایل‌های داخل ویندوز بین سشن‌ها منتقل نمی‌شوند.

---

## راه‌اندازی (یک بار)

1. **کلید Tailscale** بساز: <https://login.tailscale.com/admin/settings/keys>
   - نوع: **Ephemeral** و **Reusable** (تا نودهای تکراری در شبکه‌ات جمع نشوند)
2. در گیت‌هاب: **Settings → Secrets and variables → Actions → New repository secret**
   - `TAILSCALE_AUTHKEY` → همان کلید
   - `RDP_PASSWORD` (اختیاری) → رمز دلخواه برای کاربر `NvDAdmin`
3. دکمه‌ی **Actions → Windows Cloud RDP (auto-renewing) → Run workflow**

بعد از چند دقیقه، در لاگ این را می‌بینی:

```
Tailscale IP : 100.x.y.z
Username     : NvDAdmin
Password     : ****
Connect with : mstsc /v:100.x.y.z
```

با `mstsc` (Remote Desktop ویندوز) به همان آی‌پی وصل شو.

> اگر MagicDNS در Tailscale روشن باشد، به‌جای آی‌پی می‌توانی به نام ثابت `github-rdp-server` وصل شوی؛ این نام در همه‌ی سشن‌ها یکی است.

## چطور «هیچ‌وقت» تموم نشود

| قطعه | کارش |
|---|---|
| جاب `next` | بعد از هر سشن (چه موفق، چه تایم‌اوت، چه کرش) سشن بعدی را دیسپچ می‌کند |
| `concurrency` | تضمین می‌کند فقط یک سشن هم‌زمان اجرا شود (دو VM روی یک نام Tailscale نیفتند) |
| `grep` خودترمیم | اگر Tailscale در طول سشن قطع شود، به‌طور خودکار `tailscale up` می‌زند |
| `rdp-watchdog.yml` | هر ۳۰ دقیقه چک می‌کند؛ اگر زنجیره مرده بود، دوباره روشنش می‌کند |

### متغیرها (Settings → Secrets and variables → Actions → Variables)

| نام | پیش‌فرض | معنی |
|---|---|---|
| `MAX_CHAIN` | `0` | `0` = **بی‌نهایت** (پیش‌فرض). اگر عدد بگذاری، زنجیره بعد از همان تعداد سشن خودش می‌ایستد |
| `AUTO_RDP` | خاموش | `on` بگذار تا watchdog هم فعال شود |

### چطور متوقفش کنم

- در تب Actions، آخرین رانِ در حال اجرا **و** رانِ در صف را Cancel کن؛ زنجیره همان‌جا می‌میرد.
- یا کل ورک‌فلوی `windows-rdp.yml` را از تب Actions غیرفعال کن.
- اگر watchdog روشن است، متغیر `AUTO_RDP` را حذف/خاموش کن، وگرنه دوباره زنده‌اش می‌کند.

> ⚠️ این ورک‌فلو باید روی برنچ پیش‌فرض (`main`) باشد، وگرنه گیت‌هاب اجازه‌ی `workflow_dispatch` از طریق API را نمی‌دهد و زنجیره از حلقه‌ی دوم به بعد جلو نمی‌رود.

---

## امنیت — این را جدی بگیر

- ریپو **public** است و هر کسی می‌تواند کد را ببیند. رمز قبلی که داخل ورک‌فلو هارد‌کد شده بود (`P@ssw0rd1qazXSW@#`) را عوض کن؛ فرض کن لو رفته است.
- رمز جدید فقط از Secret یا به‌صورت تصادفی ساخته می‌شود و در لاگ ماسک می‌شود.
- یک ماشین RDP با دسترسی ادمین روی اینترنت کار خطرناکی است؛ حتماً رمز قوی بگذار و بعد از کار، زنجیره را خاموش کن.
- اگر ریپو را private کنی، دقیقه‌های رانر ویندوز (با ضریب ۲) از سهمیه‌ات کم می‌شود. در ریپوی public رایگان است.

## چرا ۴۸ ساعته‌ی قبلی کار نمی‌کرد

حلقه‌ی `for ($i=1; $i -le 2880; ...)` هیچ‌وقت به پایان نمی‌رسید، چون گیت‌هاب جاب را سر ۶ ساعت می‌کشت. الان به‌جای یک جاب طولانی، زنجیره‌ای از سشن‌های کوتاه داریم که هر کدام بعدی را روشن می‌کند.
